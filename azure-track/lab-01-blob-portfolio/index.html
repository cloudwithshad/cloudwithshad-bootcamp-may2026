💡 Beginners Guide: Core Storage Concepts

1. What is an Azure Storage Account?
Think of a secure digital warehouse. Inside this warehouse, Microsoft provides different rooms for files, tables, queues, and binary blobs. You only pay for the exact gigabytes your files occupy.

2. What is the $web container?
Think of a storefront display window facing the main street. Any document placed inside the normal warehouse rooms requires security passes and secret keys to view. But when you put your HTML files inside the special $web display window, Azure automatically makes them publicly readable by web browsers around the world.

3. What is Locally Redundant Storage (LRS)?
Think of keeping three identical copies of your document in different fireproof cabinets inside the same local office. LRS replicates your data three times within a single physical data center, providing 99.999999999% durability at minimal cost.

Architecture Layer Azure Portal Resource Role in High Availability System
Global Traffic Ingress Primary Web Endpoint Provides a secure public HTTPS URL (*.z6.web.core.windows.net) routing browser traffic directly to blob storage.

Phase 1 & 2 · Azure Portal Console

Create Resource Group & Storage Account

Page 04 · Portal Provisioning
1
Create Resource Group via Portal
1. Sign in to the Azure Portal at portal.azure.com.
2. In the top search bar, type Resource groups and select it from the list.
3. Click the + Create button in the top left toolbar.
4. On the Basics tab, configure these values:
  • Subscription: Select your active subscription.
  • Resource group: Type rg-static-portfolio-lab.
  • Region: West US 2.
5. Click the blue Review + create button at the bottom.
6. Once validation passes, click Create.
2
Create Storage Account via Portal
1. In the top search bar, type Storage accounts and select it.
2. Click + Create.
3. On the Basics tab, fill out these fields:
  • Resource group: Choose rg-static-portfolio-lab.
  • Storage account name: Type cloudshadstatic followed by a unique number (example: cloudshadstatic482). Must be 3 to 24 lowercase letters and numbers only.
  • Region: Choose the same region as your resource group.
  • Primary service: Azure Blob Storage.
  • Performance: Standard.
  • Redundancy: Locally-redundant storage (LRS).
4. Click Review + create, then click Create.
5. Wait for deployment to complete, then click Go to resource.
⚠️ Naming Rule Alert
Storage account names become part of the public web address. They must be globally unique across all Microsoft customers and contain lowercase letters only.
Phase 3 · Azure Portal Console

Enable Static Website Hosting & Routing

Page 05 · Static Web Routing
3
Activate the Static Website Blade
1. From your storage account overview, look at the left-hand navigation menu.
2. Scroll down to the Data management section.
3. Click on Static website.
4. On the main pane, select the Enabled radio button.
5. Fill in the document routing textboxes:
  • Index document name: index.html
  • Error document path: 404.html
6. Click the Save button at the very top of the pane.
4
Copy the Primary Endpoint URL
Immediately after clicking Save, Azure performs two automated actions:

1. Creates the $web Container: Azure automatically creates a special public container named $web in your account.

2. Generates the Primary Endpoint: Look at the Primary endpoint field on this same page. It will display a public URL similar to:
https://cloudshadstatic[id].z6.web.core.windows.net/

Click the small Copy to clipboard icon next to this URL. Keep this browser tab open, as this is the live web address you will share with visitors.
Phase 4 · Azure Portal Console

Upload Website Files to the $web Container

Page 06 · Artifact Deployment
5
Step 5: Prepare Local index.html & 404.html
Create these two simple HTML files on your computer using Notepad, VS Code, or any text editor:
FILE: INDEX.HTML
<!doctype html> <html> <head> <meta charset="utf-8"> <title>Azure Cloud Portfolio</title> <style> body { background: #0B131C; color: #F1F6FA; font-family: Arial, sans-serif; text-align: center; padding: 60px 20px; } h1 { color: #BFD3E2; } </style> </head> <body> <h1>Azure Cloud Engineering Portfolio</h1> <p>Hosted serverless on Azure Storage Accounts.</p> </body> </html>
6
Step 6: Upload into $web via Portal GUI
1. In your storage account, look at the left menu and locate the Data storage section.
2. Click on Containers.
3. Click on the $web container in the list.
4. In the top toolbar, click the + Upload button.
5. An Upload blob panel will open on the right:
  • Click the blue folder icon to browse your local computer.
  • Select both your index.html and 404.html files.
  • (Alternatively, simply drag and drop the files from File Explorer into the portal window).
6. Click the blue Upload button at the bottom of the panel.
7. Verify that both files appear listed inside the $web container.
Phase 5 · Browser Verification

Verify Global Ingress & Error Handling

Page 07 · Ingress Verification
7
Test 1: Verify Live Portfolio Webpage
1. Open a brand new tab in your web browser (Chrome, Edge, Firefox, or Safari).
2. Paste your copied Primary endpoint URL into the address bar:
https://cloudshadstatic[id].z6.web.core.windows.net/
3. Press Enter.
4. Confirm that your portfolio landing page loads with HTTPS security and displays your custom header: Azure Cloud Engineering Portfolio.

Why this works: Azure Storage automatically inspected the incoming request for the root path and served index.html directly from the $web container.
8
Test 2: Verify Custom 404 Error Routing
1. In the same browser tab, append a non-existent path to your web address:
https://cloudshadstatic[id].z6.web.core.windows.net/randompage.html
2. Press Enter.
3. Confirm that your custom 404.html document displays on screen.

Why this works: Because randompage.html does not exist inside $web, the Azure Storage static website engine automatically fell back to the error document path configured in Phase 3.

Clean Operations · Cost Governance

Teardown & Resource Cleanup via Portal

Page 09 · Resource Teardown
💰 Cost Governance Best Practice
Always delete lab resources when verification is complete. Because all resources were grouped inside a single resource group, deleting the resource group in the portal tears down the storage account, endpoints, and containers cleanly in one single click.
🗑️
Portal Deletion Steps
1. In the top search bar of the Azure Portal, type Resource groups and select it.
2. In the list, click on rg-static-portfolio-lab.
3. In the top command bar, click the Delete resource group button (it has a trash can icon).
4. A side drawer will appear on the right asking you to confirm: type the exact name rg-static-portfolio-lab into the text box.
5. Click the red Delete button at the bottom.
6. Click Delete one more time on the confirmation pop-up.

Azure will delete the storage account, containers, endpoints, and all stored files automatically.
