Two-Tier Segmentation & Network Isolation

Page 02 · Architecture Stack
Lightbulb: Core Networking Concepts for Beginners

1. What is an Azure Virtual Network (VNet)?
Think of a private, fenced corporate office park. Nothing inside the fence can be reached from the outside world unless you explicitly build an authorized gateway with strict security controls.

2. What are Public and Private Subnets?
Think of a front lobby versus a locked basement records vault. The public web subnet (lobby) welcomes arriving internet visitors. The private database subnet (vault) has zero exterior doors and zero public IP addresses. It only accepts connections from authenticated computers inside the internal hallway.

3. What is a Network Security Group (NSG)?
Think of a security guard with an approved guest badge list. Every data packet attempting to enter or exit a subnet is inspected against stateful priority rules.

4. What is Subnet Delegation?
Think of granting exclusive facility access to a specialized vendor. Delegating a subnet gives Azure Database for MySQL exclusive permission to deploy and manage private network interfaces directly inside your VNet.

Web Tier (Public Subnet)
Subnet CIDR: 10.0.1.0/24
Host: Ubuntu Linux 22.04 LTS (Standard_B1s)
Public IP: Dynamic / Standard SKU
Role: Serves public HTTP web traffic and acts as an internal jump host for database management.
Data Tier (Delegated Subnet)
Subnet CIDR: 10.0.2.0/24
Delegation: Microsoft.DBforMySQL/flexibleServers
Private DNS Zone: *.mysql.database.azure.com
Role: Completely isolated relational database reachable exclusively from within the virtual network.
Phase 1 & 2 · Azure Portal Setup

Create Virtual Network & Delegated Subnets

Page 03 · Virtual Network
1
Create Resource Group & VNet
1. Sign in to the Azure Portal (portal.azure.com).
2. In the top search bar, type Virtual networks and select it.
3. Click + Create.
4. In the Basics tab, configure:
• Subscription: Select your active subscription.
• Resource group: Click Create new and enter rg-cloudwithshad-week2.
• Virtual network name: vnet-cloudwithshad.
• Region: West US 2.
2
Configure IP Addresses & Subnets
5. Click the IP addresses tab.
6. Set the IPv4 address space to 10.0.0.0/16.
7. Under Subnets, click on the default subnet or click + Add subnet:
• Name: web-subnet
• Starting address: 10.0.1.0/24
• Click Add.
8. Click + Add subnet again for the database tier:
• Name: db-subnet
• Starting address: 10.0.2.0/24
• Subnet delegation: Select Microsoft.DBforMySQL/flexibleServers from the dropdown.
• Click Add.
9. Click Review + create, then click Create.
Phase 3 · Traffic Filtering

Configure Network Security Group (NSG)

Page 04 · Network Security
1
Create Web Tier NSG
1. In the Azure Portal search bar, type Network security groups and select it.
2. Click + Create.
3. Set Resource group: rg-cloudwithshad-week2.
4. Set Name: nsg-web-tier.
5. Set Region: West US 2.
6. Click Review + create, then click Create.
7. When deployment completes, click Go to resource.
2
Add Rules & Associate Subnet
8. In the left menu of nsg-web-tier, under Settings, click Inbound security rules.
9. Click + Add to create the HTTP rule:
• Service: HTTP (Port 80)
• Action: Allow • Priority: 300
• Name: Allow-HTTP-All • Click Add.
10. Click + Add to create the SSH management rule:
• Service: SSH (Port 22)
• Source: Select My IP address for secure lockdown.
• Priority: 310 • Name: Allow-SSH-Admin • Click Add.
11. In the left menu, click Subnets under Settings > Click + Associate.
12. Select Virtual network vnet-cloudwithshad and Subnet web-subnet > Click OK.
Phase 4 · Compute Provisioning

Deploy Linux Web VM in web-subnet

Page 05 · Web VM Deployment
1
Configure VM Basics
1. In the Azure Portal search bar, type Virtual machines and click Create > Azure virtual machine.
2. In the Basics tab:
• Resource group: rg-cloudwithshad-week2
• Virtual machine name: vm-web-01
• Region: West US 2
• Availability options: No infrastructure redundancy required
• Security type: Standard
• Image: Ubuntu Server 22.04 LTS x64 - Gen2
• Size: Standard_B1s (1 vcpu, 1 GiB memory)
• Authentication type: SSH public key
• Username: azureuser
• SSH public key source: Generate new key pair
2
Attach to VNet & Subnet
3. Click the Networking tab at the top:
• Virtual network: Select vnet-cloudwithshad.
• Subnet: Select web-subnet (10.0.1.0/24).
• Public IP: Select (new) vm-web-01-ip.
• NIC network security group: Select None (the subnet already has nsg-web-tier protecting it).
• Delete public IP and NIC when VM is deleted: Checked.
4. Click Review + create, then click Create.
5. Download the private key file (vm-web-01_key.pem) when prompted and save it securely.
Phase 5 · Database Provisioning

Deploy MySQL Flexible Server in db-subnet

Page 06 · MySQL Database
1
Configure MySQL Basics
1. In the Azure Portal search bar, type Azure Database for MySQL flexible servers and select it.
2. Click + Create.
3. In the Basics tab:
• Resource group: rg-cloudwithshad-week2
• Server name: mysql-cloudwithshad-unique (must be globally unique)
• Region: West US 2
• Workload type: For development or small workloads
• Compute + storage: Click Configure server, choose Burstable, B1ms (1 vCore, 2 GiB RAM, 32 GiB storage) to keep costs minimal, then click Save.
• Authentication method: MySQL authentication only
• Admin username: azureadmin
• Password: Enter a strong password and record it.
2
Select Private VNet Access
4. Click the Networking tab:
• Connectivity method: Select Private access (VNet Integration).
• Virtual network: Select vnet-cloudwithshad.
• Subnet: Select db-subnet (10.0.2.0/24).
• Private DNS integration: Leave checked Integrate with private DNS zone (Azure automatically creates and links mysql-cloudwithshad.private.mysql.database.azure.com).
5. Click Review + create, then click Create.
Note: Provisioning a flexible server typically takes 5 to 10 minutes.
Phase 6 · Verification & Testing

Connect to VM & Validate Private Database

Page 07 · Connectivity Testing
1
SSH into Web VM
1. In Azure Portal, navigate to Virtual machines > vm-web-01 and copy its Public IP address.
2. Open PowerShell or Terminal on your computer and connect using your downloaded key:
Local Terminal · SSH to Web VM
ssh -i ~/Downloads/vm-web-01_key.pem azureuser@<VM-PUBLIC-IP>
3. Once logged into the VM, install the MySQL client utility:
vm-web-01 · Install MySQL Client
sudo apt-get update && sudo apt-get install -y mysql-client
2
Query Private MySQL Server
4. In Azure Portal, navigate to your MySQL server and copy its Server name (e.g., mysql-cloudwithshad-unique.mysql.database.azure.com).
5. Connect directly across the internal virtual network:
vm-web-01 · Connect to Private Database
mysql -h mysql-cloudwithshad-unique.mysql.database.azure.com -u azureadmin -p
6. Enter your admin password when prompted.
7. Run STATUS; and SHOW DATABASES; to confirm internal connectivity.
8. Try pinging the MySQL server from your personal laptop: it will fail, proving the database is completely blocked from the public internet.

Portal Deletion Steps

2. Click on rg-cloudwithshad-week2.

4. Type rg-cloudwithshad-week2 in the confirmation field.
