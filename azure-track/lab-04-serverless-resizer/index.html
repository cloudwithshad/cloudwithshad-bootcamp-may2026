Serverless Architecture & Event-Driven Stack

Page 02 · Architecture Stack
Lightbulb: Core Serverless Concepts for Beginners

1. What is an Azure Function?
Think of an on-demand darkroom technician. Instead of paying for a full-time studio 24 hours a day, the technician stays asleep until an image arrives. When a photo is uploaded, the technician wakes up in milliseconds, resizes it, saves the thumbnail, and goes immediately back to sleep. You only pay for the exact milliseconds your code runs.

2. What is an Event Trigger?
Think of a door sensor chime. The moment a new file enters the storage container, the sensor triggers an alert that starts the function automatically without wasting compute power checking the folder repeatedly.

3. What is Pillow (PIL)?
Pillow is the gold-standard Python imaging library. It reads raw photo byte streams, calculates proportional aspect ratios, and resamples pixel matrices into clean, lightweight web thumbnails.

Ingress & Storage Layer
Azure Blob Storage: Container uploads receives high-resolution photos.
Output Container: Container thumbnails stores 200px optimized JPEG images.
Security: Private access with key-based internal connection string.
Compute & Processing Layer
Compute: Azure Function App on serverless Consumption Plan.
Runtime: Python on Linux OS.
Trigger: Blob Storage Trigger listening on uploads/{name}.
Engine: In-memory byte stream resizing via Pillow.

Phase 1 & 2 · Storage Configuration

Create Storage Account & Blob Containers

Page 04 · Storage Setup
1
Create Storage Account
1. Sign in to the Azure Portal (portal.azure.com).
2. In the top search bar, type Storage accounts and select it.
3. Click + Create.
4. In the Basics tab, configure:
• Subscription: Select your active subscription.
• Resource group: Click Create new and enter rg-image-resizer-lab.
• Storage account name: Enter a globally unique name (e.g., stgresizer[yourname], lowercase alphanumeric only).
• Region: West US 2.
• Performance: Standard.
• Redundancy: Locally-redundant storage (LRS).
5. Click Review + create, then click Create.
2
Create Dual Containers in Portal
6. When deployment finishes, click Go to resource.
7. In the left navigation menu under Data storage, click Containers.
8. Click + Container at the top:
• Name: uploads
• Anonymous access level: Private (no anonymous access)
• Click Create.
9. Click + Container again to create the output bucket:
• Name: thumbnails
• Anonymous access level: Private (no anonymous access)
• Click Create.
10. Both containers are now visible in your storage container list.
Phase 3 · Serverless Compute

Create Function App in Consumption Plan

Page 05 · Function App
1
Configure Function App Basics
1. In the Azure Portal search bar, type Function App and select it.
2. Click + Create.
3. Choose Consumption (Serverless hosting option) and click Select.
4. In the Basics tab, configure:
• Resource Group: Select rg-image-resizer-lab.
• Function App name: fn-img-resizer-[yourname] (must be globally unique).
• Do you want to deploy code or container image? Code.
• Runtime stack: Python.
• Version: 3.10 or 3.11.
• Region: West US 2.
• Operating System: Linux (default for Python functions).
2
Connect Storage & Deploy
5. Click the Storage tab at the top:
• Storage account: Select the storage account you created in Phase 1 (stgresizer[yourname]).
6. Click the Monitoring tab:
• Enable Application Insights: Yes (provides live logs and invocation telemetry).
7. Click Review + create at the bottom.
8. Validate the settings summary and click Create.
9. Deployment takes approximately 60 to 90 seconds. When completed, click Go to resource.
Phase 4 · VS Code Development & Deployment

Build with Pillow & Deploy from VS Code

Page 06 · VS Code Workflow
💡 Cloud Architect Production Note
Azure Linux Consumption Function Apps intentionally disable in-portal code editing to ensure binary dependencies (like the C-based Pillow imaging engine) compile natively on Linux container runners. We develop locally in VS Code and publish directly using the official Azure Functions Extension.
1
VS Code Setup & Dependencies
1. Open your project folder in VS Code.
2. Ensure the Azure Functions and Python extensions are installed.
3. Open requirements.txt and specify the production dependencies:
requirements.txt
azure-functions azure-storage-blob Pillow
4. Press Ctrl + Shift + P (or F1) → Select Azure Functions: Deploy to Function App...
5. Choose your target Function App from the list and click Deploy.
2
Python V2 Blob Trigger (function_app.py)
Paste the production V2 event-driven resizing logic into function_app.py:
function_app.py · Python V2 Model
import io, os, logging import azure.functions as func from azure.storage.blob import BlobServiceClient from PIL import Image app = func.FunctionApp() @app.function_name(name="resize_image") @app.blob_trigger( arg_name="myblob", path="uploads/{name}", connection="AzureWebJobsStorage" ) def resize_image(myblob: func.InputStream): logging.info(f"Processing blob: {myblob.name}, Size: {myblob.length} bytes") image = Image.open(io.BytesIO(myblob.read())) width, height = image.size new_height = round(height * 200 / width) resized = image.resize((200, new_height), Image.Resampling.LANCZOS) out_stream = io.BytesIO() resized.save(out_stream, format="JPEG", quality=85) out_stream.seek(0) conn = os.environ["AzureWebJobsStorage"] client = BlobServiceClient.from_connection_string(conn) filename = os.path.basename(myblob.name) client.get_blob_client("thumbnails", filename).upload_blob(out_stream, overwrite=True) logging.info(f"Thumbnail successfully saved to thumbnails/{filename}")
Phase 5 · Verification & Testing

Upload Photo & Inspect Resized Output

Page 07 · End-to-End Validation
1
Upload Test Photo via Storage Browser
1. Navigate to your Storage Account in the Azure Portal.
2. In the left menu, click Storage browser > Blob containers > uploads.
3. Click the Upload button in the top toolbar.
4. In the side pane, browse and select any test photo (e.g., sample.jpg, 2MB+).
5. Click Upload.
6. The image appears in the uploads container list.
2
Verify Invocations & Thumbnail Output
7. Navigate to your Function App > Functions > ResizeImage.
8. Click the Monitor or Log stream tab to see the function awaken and execute with status code Success (200).

10. Notice the file sample.jpg has appeared automatically!
11. Click on the file > click Download and inspect the properties: the width is exactly 200px and file size is dramatically reduced.

Teardown & Resource Cleanup via Portal

Page 09 · Resource Teardown
Moneybag: Cost Governance Best Practice
While serverless functions incur zero idle costs, standard storage accounts retain data and incur minor monthly storage fees. Delete the lab resource group in the Azure Portal after submitting your evidence.
Trash
Portal Deletion Steps
1. In the Azure Portal search bar, type Resource groups and select it.
2. Click on rg-image-resizer-lab.
3. Click the Delete resource group button in the top toolbar.
4. Type rg-image-resizer-lab in the confirmation field.
5. Click Delete.

Azure will automatically remove the Function App, App Service Plan, Storage Account, Application Insights, and all container data in a single automated teardown operation.
