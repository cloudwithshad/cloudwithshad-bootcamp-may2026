Azure Compute & Security Architecture

Page 02 · Architecture Stack
💡 Beginners Guide: Core Compute & Security Concepts

1. What is an Azure Virtual Machine (VM)?
Think of a rented private office unit in a cloud tower. Instead of buying physical computer hardware, Azure allocates dedicated virtual CPU cores, memory, and storage that you control fully with complete administrator access.

2. What is a Network Security Group (NSG)?
Think of a security guard desk at the building entrance. Every packet of traffic arriving at your server must show its badge. The guard checks the port number: port 22 is allowed only for administrators holding the secret SSH key, and port 80 is allowed for public visitors wanting to view the website. All other ports are blocked by default.

3. What is an SSH Keypair?
Think of a high security digital master lock and key. The public key is permanently installed in the lock on your Linux server. The private key (.pem file) stays only on your personal computer. When you connect, cryptographic handshakes authenticate you instantly without transmitting passwords across the internet.

💰 Azure Free Tier Advisory: B1s Configuration Rule
Azure includes 750 hours per month of the Standard_B1s size for 12 months. However, the portal defaults Security type to Trusted Launch, which blocks all burstable B-series sizes. In the portal creation wizard, you must switch Security type to Standard to select B1s. Additionally, on the Disks tab, change the OS disk type from Premium SSD to Standard SSD to prevent unexpected billing.
Architecture Layer Azure Portal Resource Role in System Architecture
Virtual Compute Tier Azure Virtual Machine (Standard_B1s) Runs Ubuntu Server 24.04 LTS with dedicated vCPU and 1 GiB memory for lightweight workloads.
Traffic Filtering Network Security Group (nsg-vm-web) Stateful cloud firewall enforcing inbound rule priority 100 (SSH 22) and 110 (HTTP 80).
Network Ingress Azure Public IP Address Dynamic or static IPv4 address routed through Microsoft global edge routers to your virtual NIC.
Virtual Network Azure VNet & Default Subnet Isolated private network space facilitating secure communication between NICs and subnets.
Application Tier Nginx HTTP Server (systemd) High performance web server process listening on port 80 and returning HTML web responses.

Phase 1 & 2 · Azure Portal Console

Create Resource Group & Configure Firewall Rules

Page 04 · Firewall Configuration
1
Create Resource Group via Portal
1. Sign in to the Azure Portal at portal.azure.com.
2. Search Resource groups in the top search bar and click + Create.
3. Subscription: Select your active subscription.
4. Resource group name: Type rg-virtual-machines-lab.
5. Region: Choose your preferred deployment region (such as East US).
6. Click Review + create, then click Create.
2
Create NSG & Add Firewall Rules in Portal
1. In the search bar, type Network security groups and click + Create.
2. Resource group: Select rg-virtual-machines-lab.
3. Name: Type nsg-vm-web; Region: Same as your resource group.
4. Click Review + create, then click Create.
5. Open your new nsg-vm-web resource and go to Settings > Inbound security rules.
6. Click + Add in the top bar to add these two rules:
Priority Rule Name Port Action
100 Allow-SSH 22 Allow
110 Allow-HTTP 80 Allow
Phase 3 · Azure Portal Console

Deploy Ubuntu Linux VM (Standard_B1s)

Page 05 · Compute Provisioning
3
Basics Tab Configuration
1. In the search bar, type Virtual machines and click + Create > Azure virtual machine.
2. Resource group: Select rg-virtual-machines-lab.
3. Virtual machine name: Type vm-linux-web-01.
4. Image: Select Ubuntu Server 24.04 LTS - x64 Gen2.
5. CRITICAL: Under Security type, change the dropdown from Trusted Launch virtual machines to Standard.
6. Size: Click See all sizes, search B1s, and select Standard_B1s (1 vCPU, 1 GiB memory).
7. Administrator account: Authentication type -> SSH public key.
  • Username: azureuser
  • Key pair name: Keep default vm-linux-web-01_key.
4
Disks, Networking & Key Download
1. Click the Disks tab at the top:
  • Change OS disk type to Standard SSD (locally-redundant storage).
2. Click the Networking tab:
  • NIC network security group: Select Advanced.
  • Configure network security group: Choose your existing nsg-vm-web.
3. Click Review + create at the bottom.
4. When validation passes, click Create.
5. A pop-up will appear: Generate new key pair. Click Download private key and create resource.
6. Save the downloaded vm-linux-web-01_key.pem file into your project folder.
Phase 4 & 5 · Server Configuration

Connect Over SSH & Install Nginx Web Server

Page 06 · SSH & Web Server Setup
5
Connect to Your Server via SSH
1. In the Azure Portal, open your vm-linux-web-01 overview page.
2. Copy the Public IP address displayed on the right.
3. Open your local terminal (Git Bash, Command Prompt, or Terminal on macOS/Linux).
4. Navigate to the folder where you saved your downloaded .pem key file:
  chmod 400 vm-linux-web-01_key.pem
5. Connect to your server over SSH (replace with your copied Public IP):
  ssh -i vm-linux-web-01_key.pem azureuser@<YOUR_VM_PUBLIC_IP>
6. When prompted, type yes to trust the host connection.
6
Install and Start Nginx
Now that you are connected to your Ubuntu server prompt, install Nginx and write a custom landing page:
UBUNTU SHELL · NGINX SETUP
# 1. Update package list and install Nginx sudo apt update && sudo apt install -y nginx # 2. Write custom landing page sudo bash -c 'cat <<EOF > /var/www/html/index.html <!doctype html> <html> <head><title>Azure VM Web Server</title></head> <body style="background:#0B131C;color:#E8F1F7;font-family:Arial;text-align:center;padding:80px;"> <h1 style="color:#BFD3E2">Azure Lab 2 Complete</h1> <p>Ubuntu 24.04 VM running Nginx is successfully configured.</p> </body> </html> EOF' # 3. Restart Nginx to apply changes sudo systemctl restart nginx
Phase 6 · Browser Verification

Verify HTTP Ingress & Nginx Daemon Health

Page 07 · Health Verification
7
Verify in Web Browser
1. Open a new tab in your web browser.
2. Type http://<YOUR_VM_PUBLIC_IP> into the address bar and press Enter.
3. Confirm that the dark-themed "Azure Lab 2 Complete" page loads immediately.

Security Note: Notice that typing https:// will not load because our NSG rules strictly allow port 80 (HTTP) and port 22 (SSH). All other inbound ports are blocked by default.
8
Inspect Metrics in Azure Portal
1. Go back to your vm-linux-web-01 blade in the Azure Portal.
2. In the left menu, click Monitoring > Metrics.
3. View real-time charts for Percentage CPU, Network In Total, and Disk Read Operations.
4. Confirm that the VM state shows Running with normal operating health metrics.

Clean Operations · Cost Governance

Teardown & Resource Cleanup via Portal

Page 09 · Resource Teardown
💰 Avoid Unintended Virtual Machine Charges
Virtual machines incur charges when left running unless properly deallocated. Deleting the parent resource group removes the VM, OS disk volumes, network interfaces, public IP addresses, and security groups in one clean operation.
🗑️
Portal Deletion Steps
1. In the top search bar of the Azure Portal, search Resource groups.
2. Click on rg-virtual-machines-lab.
3. Click the Delete resource group button in the top toolbar.
4. Type rg-virtual-machines-lab into the confirmation field.
5. Click the red Delete button, then click Delete once more to confirm.

Azure will delete the VM, disk storage, public IP, and network interface automatically.
