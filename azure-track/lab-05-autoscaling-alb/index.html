💡 Beginners Guide: Core Elastic Concepts

1. What is an Azure Load Balancer?
Think of an airport TSA line director. When a crowd of travelers arrives at the security checkpoint, the director sends each person to the shortest open lane. In Azure, the Load Balancer sits between the public internet and your servers, distributing incoming user requests evenly across healthy virtual machines so no single server gets overwhelmed.

2. What is a Virtual Machine Scale Set (VMSS)?
Think of an elastic rubber band fleet. Instead of manually creating and managing five separate computers, a VMSS manages a fleet of identical virtual machines based on one central blueprint. It can automatically clone new instances or terminate idle ones in response to demand.

3. What is Autoscale?
Think of a digital thermostat. When the room gets too hot (CPU utilization rises above 70%), the thermostat turns up the air conditioning (spawns an extra VM). When the room cools down (CPU drops below 30%), it turns off the extra unit to save power and money.

Phase 3: Traffic Filtering

Configure Network Security Group (NSG)

Page 05 · Standard Load Balancer Setup

A Network Security Group acts as a stateful perimeter firewall. To allow public internet visitors to reach your Nginx web servers while still allowing SSH administrative access, configure these explicit inbound rules:

1
Search Network security groups and click Create.
2
Resource group: rg-autoscaling-lab. Name: nsg-web-mgmt.
3
Navigate to Inbound security rules and add permissions for Port 80 and Port 22.
Priority Rule Name Port Protocol Action
100 Allow-SSH 22 TCP Allow
110 Allow-HTTP 80 TCP Allow
🛡️ Production Security Tip
For enhanced security in production, lock down Port 22 source IP to My IP instead of Any, or deploy Azure Bastion to eliminate public SSH exposure entirely.
Phase 4: Elastic Fleet

Deploy the VM Scale Set and Cloud-Init

Page 06 · Virtual Machine Scale Set
1
Basics: Name vmss-web-auto, Image: Ubuntu Server 24.04 LTS, Size: Standard_B1s, Auth: SSH key (user: azureuser).
2
Scaling Tab: Set instance counts to Minimum 1, Maximum 6, Default 1.
3
Load Balancing: Enable Load Balancer, create new: lb-web-auto (SKU: Standard). Probe: TCP port 80. Rule: port 80 to 80.
4
Networking: Attach to vnet-autoscale and web-subnet. In Advanced NIC settings, select nsg-web-mgmt.
Automated Bootstrapping Principle
Never configure scaled VMs by manually SSH-ing into them. When traffic spikes, new VMs spin up from bare images. Custom Cloud-Init data guarantees every new VM boots with Nginx pre-configured.
Advanced Tab: Custom Data (Cloud-Init)
#cloud-config package_upgrade: true packages: - nginx runcmd: - systemctl enable nginx - systemctl start nginx - echo "<h1>Azure VM Scale Set + Load Balancer</h1><p>Instance: $(hostname)</p>" > /var/www/html/index.html

Phase 6: Define Custom Autoscale Rules

Rule 1: Scale-Out (Expand Fleet)
Metric: Percentage CPU · Time window: 5 minutes
Condition: Greater than 70% · Action: Increase count by 1
Rule 2: Scale-In (Contract Fleet)
Metric: Percentage CPU · Time window: 5 minutes
Condition: Less than 30% · Action: Decrease count by 1
Cooldown Protection
Autoscale rules include default cooldown periods (typically 5 to 10 minutes) to prevent fleet flapping (rapidly creating and destroying instances).
